# Field Notes

Composite case studies drawn from sanitized field work: the methods are real
and so are the traps, but each note is assembled from more than one
engagement and rewritten until no system, value, name, or domain survives.
Systems become "a partner API", "a hosted job pipeline", or "a licensing
service"; commands appear with `$BASE` and `$TOKEN` placeholders. Treat a
note as a worked lesson, not as a transcript of one specific engagement.

The point is the method, not the war story. A note that only says "we got it
working" teaches nothing; a note that shows which phase caught which mistake
teaches the phase.

## How to read a field note

Facts carry a date and an evidence grade: `[OBS]` observed live, `[REP]`
reported secondhand, `[INF]` inferred and still untested.

Timelines follow the five phases: Perceive, Model, Execute, Verify, Evolve.
Each note's "patterns used" list names techniques from the
[pattern library](../PATTERNS.md).
